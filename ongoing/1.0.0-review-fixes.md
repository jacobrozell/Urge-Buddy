## 1. App lock bypass via URL, notification, and quick action

**Lane:** Security · Medium · 2026-11-01 [Security Review](6d1dfc4e-f07b-49ca-88c5-77834e8a743f)

`LockScreen` is an overlay. `fullScreenCover` and `.sheet` are attached after it, so `trackboth://urge`, `trackboth://checkin`, a check-in notification, and the urge quick action could show recovery data while the app was locked. A flow already on screen stayed up after backgrounding.

**Locations:** `TrackBoth/App/RootView.swift:62-69` · `TrackBoth/App/AppDelegate.swift:34-44` · `TrackBoth/App/AppRouter.swift:31-33`

**Deliverables:**
- [x] Queue `present` while the lock is on, and hide a visible flow when the app backgrounds (2026-11-01, uncommitted)
- [x] Show the queued flow only after unlock
- [x] Unit tests: `testPresentQueuesUntilUnlocked`, `testHoldForLockHidesTheVisibleFlow`
